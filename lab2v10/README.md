## Опис проєкту

Проєкт є реалізацією класу `Computer` мовою C# в рамках Лабораторної роботи №2 з дисципліни «Об'єктно-орієнтоване програмування». Програма демонструє використання перевантажених конструкторів, ланцюгового виклику `: this()`, валідації даних у властивостях, реалізації деструктора та роботи збирача сміття (Garbage Collector).

---

## Структура класу `Computer`

### 1. Приватні поля
* `_cpu` (`string`) — назва процесора.
* `_ramGB` (`int`) — обсяг оперативної пам'яті в гігабайтах.
* `_storageGB` (`int`) — обсяг накопичувача в гігабайтах.

### 2. Властивості
* `CPU` — повертає назву процесора або `"Unknown CPU"`, якщо значення порожнє.
* `RAMGB` — має валідацію: обсяг пам'яті повинен бути більшим за 0 (інакше викидає `ArgumentException`).
* `StorageGB` — має валідацію: обсяг накопичувача повинен бути більшим за 0 (інакше викидає `ArgumentException`).

### 3. Конструктори
* **Параметризований:** `Computer(string cpu, int ramGB, int storageGB)` — ініціалізує властивості об'єкта.
* **За замовчуванням:** `Computer() : this("Intel i5", 8, 256)` — використовує ланцюговий виклик `: this()`, передаючи базові значення.

### 4. Методи
* `RunBenchmark()` — розраховує умовний результат продуктивності ПК та виводить його в консоль.
* `GetInfo()` — повертає рядок із технічними характеристиками комп'ютера.

### 5. Деструктор (Фіналізатор)
* `~Computer()` — викликається збирачем сміття при вивільненні пам'яті об'єкта та сповіщає про це у консолі.

---

## Демонстрація роботи

1. Створення об'єкта через конструктор за замовчуванням.
2. Створення об'єкта через параметризований конструктор.
3. Обробка помилки валідації при спробі передати від'ємне значення RAM.
4. Примусовий запуск `GC.Collect()` та `GC.WaitForPendingFinalizers()` для виклику деструктора.
