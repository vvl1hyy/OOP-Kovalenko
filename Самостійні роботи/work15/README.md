# Самостійна робота №15: Делегати й лямбда-вирази

**Виконав:** Коваленко Владислав, група ІПЗ 3-2

## Опис
Консольний застосунок з реалізацією статичного класу `CollectionUtils` (`Map`, `MaxBy`, `Filter`, `ForEach`) з використанням делегатів і лямбда-виразів для різних типів колекцій (`List<int>`, `List<string>`, `List<Product>`).

## Звіт

### Чому делегати корисні для створення таких утиліт?
Делегати дозволяють передавати в метод саму логіку (умову фільтрації, правило перетворення або дію) як параметр. Завдяки цьому цикл обходу колекції пишеться один раз, а поведінку легко змінювати без дублювання коду.

### Як лямбда-вирази спрощують виклик цих методів?
Лямбда-вирази дозволяють написати коротку функцію прямо в місці виклику (наприклад, `p => p.Price > 1000`), не створюючи окремі іменовані методи чи класи. Код читається коротше й зрозуміліше.

### Порівняння з вбудованими LINQ-операторами
- `Map<TSource, TResult>` — аналог `Select()`, але тут повертається готовий `List<TResult>`, а не відкладений ітератор (`yield`).
- `Filter<T>` — аналог `Where()`, приймає `Predicate<T>` і повертає відфільтрований список.
- `MaxBy<T, TKey>` — аналог вбудованого `MaxBy()`, шукає елемент за вибраним ключем.
- `ForEach<T>` — схожий на `List<T>.ForEach()`, але працює з будь-яким `IEnumerable<T>` через `Action<T>`.

Вбудований LINQ зручніший у реальних проєктах (має відкладене виконання та оптимізації), а власні утиліти корисні для навчання або коли потрібна своя специфічна логіка.
